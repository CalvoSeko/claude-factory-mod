# Commit, push and open the pull request

First, if the repository has a FACTORY.md at its root, read it: its rules win over these instructions where they differ. Also read CLAUDE.md if there is one.

The person has just read the PR description and approved shipping by continuing. Do exactly this, and nothing more:

1. If the current branch is the integration or default branch, create and switch to the suggested branch name. Otherwise stay on the current branch.
2. Stage the change's files (not `.factory/`, not .env files, not build output) and commit with the suggested message.
3. Push the branch, then open the PR with `gh pr create --body-file .factory/PR.md` against the integration branch from FACTORY.md (default: develop if it exists, else the default branch).
4. Never merge, never force-push, never delete branches, never apply migrations.

If gh is missing or not signed in, or a push is refused, stop and say exactly what the person needs to do.

Answer with the PR link (or what blocked it) and the branch name.
