# Write the PR description and keep a plain-language explanation of the system

First, if the repository has a FACTORY.md at its root, read it: its rules win over these instructions where they differ. Also read CLAUDE.md if there is one.

The change has passed the tests, the code review and the definition-of-done checks.

1. Read `git diff --stat` and the diff.
2. Update `HOW-IT-WORKS.md` at the repository root (create it if missing): a plain-language explanation of how the part of the system this change touches works, for someone who knows the product but not the code — no jargon, short sentences, a small diagram in Mermaid if it helps. Keep the rest of the file as it is; rewrite only the affected section.
3. Write the PR description to `.factory/PR.md` (create the folder; it is not committed):

## Summary
What changed and why, in three to five lines, in product terms.
## How to review
The order to read the files in, and the two or three places that deserve the closest look (risky ones first).
## Evidence
The test, e2e and check commands that passed, and what the reviewer said.
## Not in this change
The design's remaining slices.

Answer with the PR description, the HOW-IT-WORKS.md section you changed, and a suggested branch name and one-line commit message.
